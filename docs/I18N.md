# Translations

The plugin declares `Text Domain: kloudstack-azure-observability` and `Domain Path: /languages`.
`languages/kloudstack-azure-observability.pot` is committed so translators can work from the repo,
and CI regenerates it on every run and fails if it has drifted.

Regenerate after changing any user-facing string:

```bash
wp i18n make-pot . languages/kloudstack-azure-observability.pot \
  --slug=kloudstack-azure-observability \
  --domain=kloudstack-azure-observability \
  --exclude=vendor,tests,benchmark,docs,scripts,legacy,loader,node_modules
```

## Coverage is partial, deliberately

As of 2.0.0-rc1, **43 strings are extracted from 4 files**. Three areas are not yet wrapped:

| File | State |
|---|---|
| `src/Admin/Diagnostics.php` | **Not wrapped.** ~26 `self::result()` call sites, each with a label and a message. Rendered on the Tools page and in Site Health |
| `src/Admin/SettingsPage.php` | **Partly wrapped.** The `toggles()` definitions carry unwrapped `label` and `description` values; the rest of the file is wrapped |
| `src/Admin/SiteHealth.php` | **Mostly wrapped.** A handful remain |

Roughly 80 strings in total. This is a known gap, recorded rather than discovered later.

It was deliberately not closed before rc1: those files' exact message text is asserted in the test
suite, so wrapping them is ~80 mechanical edits with real regression surface, immediately before a
release, for something that blocks nothing. WordPress.org treats internationalisation as a best
practice rather than a submission requirement.

**Do it as one focused pass while review is in queue**, not piecemeal.

## What must not be translated

`Log::` messages are developer-facing and go to `debug.log`. They stay in English so that a support
engineer reading a customer's log is not reading it in a language they do not speak.

The diagnostics *support report* is a genuine judgement call rather than an oversight. Its strings
are user-facing and belong in the user's language on screen, but the report exists to be pasted
into a support ticket — so localising it means KloudStack support receives reports in languages
they may not read. If that becomes a real problem, the fix is a separate untranslated
machine-readable block in the report, not reverting the UI to English.
